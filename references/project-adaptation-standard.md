# lstest 项目适配标准

`lstest` 是跨项目测试验证和压测的标准执行框架。它来自既有项目的通用实践，用于避免每个新项目重复确认日志、异常、播放、声卡、停止和结果口径。

## 复用边界

新项目使用 `skill-creator` 创建独立的项目适配测试 Skill，并把项目需求映射到 `lstest` 的 profile、`ScenarioRuntime`、场景接口和结果规范。不得直接修改 `lstest` 的通用逻辑，也不得复制后形成无法回收改进的分叉版本。

项目适配 Skill 可以引用 `lstest` 的公开 Python 模块，也可以在其适配代码中按公开接口调用；项目输出一律写在项目工作区，不能写入 `lstest` 安装目录。

## 默认继承项

以下项是项目适配 Skill 的既定标准，不需要重新设计：

- 运行前读取 `plan.md`，执行 profile、依赖、输入、端口和安全前置检查。
- 端口持续采集、按端口保存 `.log` 原始证据；不生成串口 `.bin` 或默认合并日志。
- Edge TTS 使用显式语料 manifest，并校验音频规格、时长、响度和 SHA-256。
- 播放默认使用操作系统当前默认 Render 声卡；只有项目配置显式提供稳定设备 key 时才绑定该设备。显式 key 无效时立即 `BLOCKED`，不得回退。
- 每次播报声明期望原始识别字段；每条最终识别结果关联一次播报。无播报结果、单播报多结果、内容错配、无播报唤醒和单播报多唤醒结果都记录异常并使当前通过轮失败。
- 离线算法 `keyword`、`intent` 与在线原生结果先保存为 raw；业务转换只写入 `normalized`。
- 多唤醒词按 profile 的有序需求表逐项播报、逐项确认，禁止任意唤醒命中即通过。
- 每轮打印并写入从任务开始连续累计的异常统计；串口重连、设备重启和轮次变化均不得清零。
- 每轮动作捕获异常并保留证据，尽量继续后续轮次；仅在前置条件无法执行、收到停止请求或不可恢复的任务级故障时结束。
- 每次启动和检测到重启后，先等待 profile 初始化完成 marker，再按白名单发送并验证所有 `safe_init` 命令。命令失败按 profile 重试；无回执只能由发送后的 profile 旁证确认成功，不能把沉默视作成功。恢复重试耗尽默认请求安全停止；项目每轮新动作前检查公共运行时的停止原因。
- 使用统一的 `PASS`、`EXPECTED`、`WARN`、`FAIL`、`BLOCKED`、`ABORTED`、`STOPPED` 口径及结构化汇总。

## 项目必须提供的差异

项目适配 Skill 仅补充以下项目事实：

- 非敏感 profile：端口角色、允许命令、初始化/重启/业务 marker、关联字段、唤醒词需求表和观察规则；每个初始化命令的回执规则、无回执旁证和重试/超时参数。
- 项目串口或网络适配器：将原生日志/消息解析为 raw 字段、关联 ID 与证据引用。
- 场景：语料、音频 manifest、业务前置状态、合法动作和项目 oracle。
- 需求表：多唤醒词顺序、离线/在线期望值、压测轮次、超时和停止条件。
- 项目专属 fixture：正例、反例、分段、重叠、乱码和异常回执样本。

## 适配完成条件

项目 Skill 在真机压测前必须通过 `--help`、无硬件 preflight、至少一个正常 smoke、一个受控失败/异常场景和中断/停止路径验证。新项目的 profile、适配器、场景和测试由项目 Skill 自己维护；通用规则需要改进时，回到 `lstest` 通过回归测试更新，再由后续项目继承。
